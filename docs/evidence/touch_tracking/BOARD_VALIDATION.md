# 触摸跟踪现场记录（2026-11-01）

硬件：`build/touch_capture_v3`，GT1158/800×480，实际BSP `build/touch_capture_v3_sw`。

## 已确认

- 阶段A中央与四角触摸、紫色十字和实时显示通过，详见touch_stage_a记录。
- 初版点击成功但不画框：原接口要求蓝色掩码快照帧号；已增加TOUCH_MODE原始帧来源、年龄及错误代数校验。新接口仿真通过，保留蓝色模式原校验。
- 初版逐帧全图分割在移动时易LOST，曾出现框收缩至32×32。实际完整RGB抓帧复现了完整候选仍在、却被已缩小的面积关联拒绝；修复完整区域颜色统计与初始尺度锚点。
- `app_fast`改为局部前景/背景直方图搜索、积分图与运动预测，初始化才要求椭圆筛选。用户确认“明显改善，移动和停住都能保持”。
- 舵机起初未供电；接上电源后继续测试。曾发生源帧19305停更、frame_error，PS仍能响应。按用户要求重启PS/PL后帧恢复；不是已经根治所有间歇性视频停帧。
- 重启后恢复原PD参数、方向与用户之前选择的宽范围实验；从保存姿态恢复，没有回中。用户最终明确确认“绿框与云台跟随正常，能停稳”。因此蓝色点击+双轴PD已现场通过。

## 最新反馈与待验收

用户指出框的宽高在移动时变化频繁，静止时较好。多尺度搜索可能造成此类尺寸波动。已在`app_shape`增加独立显示宽高稳定器，保留`app_fast`及tag `touch-blue-pd`回退；不改变原始中心、搜索器或PD输入。

主机检查：外观19625项，运行时363项，PD采样12项，尺寸稳定809项均通过。运行时检查明确比较原始PD坐标和稳定后的MMIO框，尺寸检查覆盖移动中心、交替宽高、持续缩放、重复帧、重选及边界。ARM实编译16个C文件，`_end=0x00300590`低于VDMA帧缓存0x01100000。复用完全相同的v3硬件bit/XSA，未改时钟及RTL。尺寸稳定的现场效果待用户实际移动目标确认。

`app_shape`已完成JTAG下载和启动。下载前manual保存实际2334/1174μs，重新加载后在PWM关闭时恢复该姿态，再恢复此前宽范围实验及PD自动；普通固件命令均收到ACK。串口显示源帧持续更新、err=0，尚未重新点击时无目标并保持原姿态。该记录只证明程序运行与恢复流程，不代表尺寸稳定现场验收完成。

红色、白色瓶盖和多色多目标点击切换尚未现场验收。共用算法的合成检查已通过，不能代替这些实物测试。PL外观加速仅评估，尚未实现。

## 点击后跳框及跟随断续复查

`app_shape`现场反馈仍跳框、跟随卡顿，不能标记尺寸问题已验收。日志显示原始目标valid频繁失效；完整静态实拍帧回放也复现旧搜索器136/160像素宽度循环。已修正搜索尺度代价及交替网格相位，真实回放、合成回归及`app_search_stable`编译下载通过；恢复原姿态及PD自动后等待重新点击的现场测试。详见[SEARCH_STABILITY.md](SEARCH_STABILITY.md)。
